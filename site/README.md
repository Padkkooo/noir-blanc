# Noir&Blanc — сайт с PostgreSQL и pgAdmin

Учебный проект: интернет-магазин парфюмерии. Сайт больше не хранит корзину и заказы
в `localStorage` «насовсем» — они сохраняются в PostgreSQL. pgAdmin используется как
удобное окно, чтобы смотреть и редактировать эту же базу.

## 1. Архитектура (как всё связано)

```
Браузер
  public/*.html + js  ──fetch('/api/...')──►  Express (server.js)
       ▲                                           │
       │  HTML/CSS/JS                              │ pg (Pool)
       │                                           ▼
       └──────────────────────────────────  PostgreSQL: noir_blanc
                                                   ▲
                                                   │ тот же сервер, другой клиент
                                                pgAdmin 4
```

Важно: **pgAdmin не является частью сайта и не «подключается» к нему напрямую**.
pgAdmin — это графический клиент PostgreSQL. Он подключается к тому же серверу
PostgreSQL, что и `server.js`, и видит те же таблицы и данные.

Сайт с базой общается только через сервер Express. Браузер не ходит в PostgreSQL
напрямую, потому что для этого пришлось бы отдать логин и пароль БД в JavaScript,
а любой пользователь смог бы их увидеть.

## 2. Быстрый запуск

**Самый простой способ (каждый раз):**

- двойной клик по `start.bat` в папке проекта **или**
- двойной клик по ярлыку **«Запуск Noir&Blanc»** на рабочем столе.

Откроется чёрное окно, запустится сервер и через пару секунд сам откроется браузер
с сайтом <http://localhost:3000>. Окно закрывать нельзя — пока оно открыто, работает
сайт. Остановка: `Ctrl+C` или закрыть это окно.

Служба PostgreSQL (`postgresql-x64-18`) стоит в автозапуске Windows, поэтому
отдельно запускать базу не нужно. pgAdmin для работы сайта тоже не нужен — он
нужен только чтобы смотреть таблицы.

**Через терминал:**

1. Убедитесь, что служба PostgreSQL запущена (Windows → «Службы» →
   `postgresql-x64-18`).
2. В папке проекта выполните:

```powershell
npm install   # только при первом запуске
npm start
```

3. Откройте <http://localhost:3000>.
4. Зарегистрируйтесь, добавьте товар в корзину и оформите заказ.
5. Откройте pgAdmin и посмотрите таблицы `users`, `cart_items`, `orders`,
   `order_items` — там появятся ваши данные. Сообщения из формы «Свяжитесь
   с нами» сохраняются в `contact_messages`.

Параметры подключения лежат в `.env`:

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=noir_blanc
DB_USER=postgres
DB_PASSWORD=2009
PORT=3000
```

Если база ещё не создана, её можно пересоздать скриптом `db/schema.sql`
(он не удаляет данные, можно запускать повторно):

```powershell
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d postgres -c "CREATE DATABASE noir_blanc ENCODING 'UTF8';"
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -d noir_blanc -f db/schema.sql
```

## 3. Подключение pgAdmin (по шагам)

1. Запустите **pgAdmin 4** (Пуск → pgAdmin 4).
2. В левом дереве найдите **Servers** → правой кнопкой →
   **Register → Server…** (Зарегистрировать → Сервер).
3. Вкладка **General**:
   - **Name**: `Noir&Blanc local` (любое понятное имя).
4. Вкладка **Connection**:
   - **Host name/address**: `localhost`
   - **Port**: `5432`
   - **Maintenance database**: `postgres`
   - **Username**: `postgres`
   - **Password**: `2009`
   - галочка **Save password** — чтобы не вводить каждый раз.
5. (Необязательно) вкладка **Advanced** → **DB restriction**: `noir_blanc` —
   тогда pgAdmin покажет только нужную базу.
6. Нажмите **Save**.

Дальше в дереве:

```
Servers
└── Noir&Blanc local
    └── Databases
        └── noir_blanc
            └── Schemas
                └── public
                    └── Tables
                        ├── brands
                        ├── perfumes
                        ├── users
                        ├── sessions
                        ├── cart_items
                        ├── orders
                        ├── order_items
                        └── contact_messages
```

Как посмотреть данные:

- правой кнопкой по таблице → **View/Edit Data → All Rows**
  (Просмотр/редактирование данных → Все строки);
- или **Tools → Query Tool** и запрос:

```sql
SELECT p.perfumeid, b.brandname, p.name, p.price
FROM perfumes p
JOIN brands b USING (brandid)
ORDER BY p.perfumeid;

SELECT o.orderid, u.email, o.totalamount, o.status, o.orderdate
FROM orders o
JOIN users u USING (userid)
ORDER BY o.orderid DESC;

SELECT * FROM order_items;

SELECT messageid, name, email, message, status, createdat
FROM contact_messages
ORDER BY createdat DESC;
```

Схему связей можно посмотреть так: правой кнопкой по базе `noir_blanc` →
**Generate ERD** (если пункт доступен в вашей версии pgAdmin).

## 4. Таблицы и связи

| Таблица | Назначение | Ключи и связи |
|---|---|---|
| `brands` | бренды | PK `brandid` |
| `perfumes` | товары | PK `perfumeid`, FK `brandid → brands` |
| `users` | пользователи | PK `userid`, UNIQUE `email` |
| `sessions` | сессии входа | PK `token`, FK `userid → users` |
| `cart_items` | корзина | PK (`userid`, `perfumeid`), FK на `users` и `perfumes` |
| `orders` | заказы | PK `orderid`, FK `userid → users` |
| `order_items` | состав заказа | PK `orderitemid`, FK `orderid → orders`, FK `perfumeid → perfumes` |
| `contact_messages` | сообщения из формы обратной связи | PK `messageid`, статус `Новое` |

Связи: один бренд — много товаров; один пользователь — много заказов и позиций
корзины; один заказ — много позиций; каждая позиция ссылается на товар.

Внешние ключи не дают создать заказ несуществующего пользователя или позицию
несуществующего товара. `ON DELETE CASCADE` у `sessions`, `cart_items` и
`order_items` автоматически чистит зависимые строки.

## 5. API сервера

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/health` | проверка подключения к БД |
| GET | `/api/products` | товары (можно `?search=...&brand=...`) |
| GET | `/api/brands` | список брендов |
| POST | `/api/auth/register` | регистрация + сессия |
| POST | `/api/auth/login` | вход |
| POST | `/api/auth/logout` | выход |
| GET | `/api/auth/me` | текущий пользователь |
| GET | `/api/cart` | корзина пользователя |
| POST | `/api/cart` | добавить товар |
| PATCH | `/api/cart/:perfumeid` | изменить количество |
| DELETE | `/api/cart/:perfumeid` | удалить товар |
| POST | `/api/cart/merge` | перенести гостевую корзину в БД после входа |
| POST | `/api/orders` | оформить заказ (транзакция) |
| GET | `/api/orders` | история заказов с составом |
| PATCH | `/api/account` | изменить имя в личном кабинете |
| POST | `/api/account/password` | сменить пароль |
| POST | `/api/contact` | отправить сообщение из формы «Свяжитесь с нами» |

## 6. Как это работает внутри (для защиты)

**Регистрация.** Пароль не хранится в открытом виде. Сервер считает хеш
`crypto.scryptSync(password, salt, 64)` и кладёт в `users.passwordhash` строку
`scrypt$соль$хеш`. При входе хеш считается заново и сравнивается через
`timingSafeEqual`.

**Сессия.** После входа сервер создаёт случайный токен, сохраняет его в таблице
`sessions` и отправляет браузеру cookie `nb_session` с флагами `HttpOnly`
(JavaScript не может прочитать) и `SameSite=Lax`. На каждом запросе сервер по
cookie находит пользователя в БД. Выход удаляет строку из `sessions`.

**Корзина.** У гостя корзина лежит в `localStorage`. После входа `auth.js`
вызывает `/api/cart/merge`, и позиции переносятся в `cart_items` с привязкой к
`userid`. Дальше все изменения идут через API и сохраняются в PostgreSQL.

**Заказ.** `POST /api/orders` выполняет транзакцию:
1. блокирует строки корзины (`SELECT ... FOR UPDATE`);
2. считает сумму **по ценам из БД**, а не по тем, что прислал браузер;
3. вставляет запись в `orders`;
4. вставляет позиции в `order_items`;
5. очищает `cart_items`;
6. делает `COMMIT`.

Если на любом шаге ошибка — `ROLLBACK`, и база остаётся в согласованном
состоянии. Это пример свойств ACID.

**Цены.** Каталог при загрузке получает актуальные цены из `/api/products`,
поэтому страница не расходится с базой.

**Безопасность SQL.** Все значения передаются в `pool.query` отдельными
параметрами (`$1`, `$2`, ...), поэтому SQL-инъекции через поля формы не проходят.

**Каталог.** Фильтры работают в браузере: карточки товаров содержат
data-атрибуты (бренд, категория, тип, цена), а `product-search.js` скрывает
неподходящие и сортирует оставшиеся. Цены и характеристики при загрузке
синхронизируются с `/api/products`, поэтому фильтр по цене использует данные
из PostgreSQL, а не только цифры, вручную вписанные в HTML. Панель фильтров
скрыта за кнопкой «Фильтры»: её можно раскрыть, выбрать нужное и свернуть
обратно, а число активных фильтров показывается на самой кнопке.

**Личный кабинет.** Для гостя в шапке отображается ссылка «Авторизация», а
после входа — иконка профиля после корзины. Иконка ведёт на `account.html`.
В кабинете видно имя, email, дату регистрации, количество заказов и сумму
покупок; можно изменить имя, сменить пароль и выйти. Пароль меняется через
`POST /api/account/password`: сервер проверяет текущий пароль, хранит только
новый хеш и завершает остальные сессии.

**Обратная связь.** `contact.js` отправляет форму на `POST /api/contact`.
Сервер проверяет поля и вставляет сообщение в таблицу `contact_messages`;
посмотреть его можно в pgAdmin. Почта при этом не отправляется: для реальной
отправки писем нужен SMTP-сервер с логином и паролем, поэтому в учебном
проекте сообщения сохраняются в БД.

**Кнопка «Наверх».** `ui.js` добавляет кнопку на страницы каталога и истории
заказов; она появляется после прокрутки примерно на 300 px.

## 7. Что показать/рассказать на защите

- Трёхуровневая архитектура: клиент (HTML/CSS/JS) → сервер (Express) →
  СУБД (PostgreSQL).
- Почему браузер не подключается к БД напрямую: пароль БД попал бы в исходники
  страницы; PostgreSQL не понимает HTTP; нужна серверная валидация.
- pgAdmin — инструмент администратора, а не часть сайта. Сайт работает без
  открытого pgAdmin; pgAdmin просто смотрит в ту же базу.
- Нормализация: бренды вынесены в `brands`, товары в `perfumes`, состав заказа —
  в `order_items`, а не одной строкой.
- Первичные и внешние ключи, UNIQUE на email, CHECK на цену/количество.
- Индексы по `userid` и `orderid` ускоряют выборки корзины и заказов.
- Транзакция при оформлении заказа и хеширование паролей.
- Гостевая корзина → слияние с серверной после входа.

## 9. Если что-то не работает

- **`Не удалось подключиться к PostgreSQL`** — проверьте, что служба
  `postgresql-x64-18` запущена, пароль в `.env` совпадает с паролем `postgres`.
- **`password authentication failed`** — неверный `DB_USER`/`DB_PASSWORD`.
  В старом `.env` у пользователя был лишний пробел, из-за него вход не работал.
- **`EADDRINUSE: 3000`** — порт занят: закройте другой `node server.js` или
  поменяйте `PORT` в `.env`.
- **Порт 5432 занят другой версией PostgreSQL** — проверьте порт в pgAdmin
  (свойства сервера → Connection) и в `.env`.
- **В pgAdmin пусто** — убедитесь, что смотрите базу `noir_blanc`, а не старые
  `Noir$Blac` / `NoirBlac` (они остались от предыдущих попыток и не используются).
- **Сайт открыт как файл `file://`** — так API работать не будет. Открывайте
  именно <http://localhost:3000>.
